The problem

Every team hits this in month three

Four things go wrong, and all four of them report success.

  • The agent reports success on work that never shipped.
  • Tests pass against the assumption the code itself made — so the suite agrees with the bug.
  • CI is green, git log is clean, and the host is serving a build four commits old.
  • Nobody can tell which AI-authored changes were verified and which were waved through.

This is not a prompting problem. It is a verification and control problem — the most expensive failure mode in AI-assisted engineering right now, because it stays invisible until a customer finds it.

The rule everything here is built on: audit the running artifact, never the reporting channel. Live URL over git log. Rendered file over build output. The actual database row over the write that “succeeded.”
